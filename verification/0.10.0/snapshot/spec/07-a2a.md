# 7. SAGE agent card and A2A integration

Target: **0.10.0**. Requirements: R-4, R-8, R-9, R-14, R-28 to R-30.
Legacy `vectors/did.json` and `vectors/jcs.json` cover earlier shapes only.

## 1. Card — CARD-01 (R-4, R-28, R-30)

The SAGE card is a signed discovery assertion. It is neither a replacement
for current registry resolution nor a claim of conformance to an external
A2A Agent Card schema. An A2A adapter can carry this assertion separately;
it MUST NOT rename a custom JCS signature as a W3C Data Integrity suite.
The earlier `Ed25519Signature2020`/`EcdsaSecp256k1Signature2019` labels are
not accepted for the following proof.

The UTF-8 JSON object is at most 65536 bytes and follows chapter 02. All
members below are mandatory except `description` and `capabilities`;
unknown members, duplicate members and null values MUST be rejected.

| Member | Value and limit |
|---|---|
| `version` | exact string `0.10.0` |
| `id` | canonical DID, chapter 06 |
| `recordVersion` | canonical decimal registry version string, chapter 09 |
| `name` | nonempty string, at most 128 UTF-8 bytes |
| `description` | string, at most 4096 UTF-8 bytes; display data only |
| `services` | exact registry `services` array, chapter 09 |
| `capabilities` | up to 64 unique nonempty ASCII names, each at most 64 bytes, sorted by ASCII bytes; advisory only |
| `issued`, `expires` | integer Unix seconds, 0 through 9007199254740991 |
| `proof` | object in section 2 |

`issued <= now < expires` and `0 < expires-issued <= 300` MUST hold, with
no additional expiry grace. A clock whose accuracy cannot be trusted causes
rejection. The card MUST NOT contain private keys or an alternative key
source. An advertised capability grants no authorization.

## 2. Proof — CARD-02 (R-8, R-19, R-28, R-29)

`proof` has exactly `type`, `verificationMethod`, `alg`, `proofValue`.
`type` is `SageAgentCardSignature0_10_0`; `verificationMethod` is a full DID
URL naming an accepted signing key belonging to `id`; `alg` is the exact
chapter 11 algorithm name. `proofValue` is canonical unpadded base64url of
the signature bytes in chapter 01 (at most 87 characters).

The signer constructs a copy with **only `proof.proofValue` removed** and
signs `ASCII("sage-card-0.10.0") || 0x00 || JCS(copy)`. Thus algorithm, key,
proof type and all timestamps are covered. There is exactly one proof;
multiple proofs are rejected. No remote JSON-LD context is fetched.

## 3. Verification — CARD-03 (R-4, R-8, R-9, R-36)

1. Enforce size/schema/time bounds before resolution or signature work.
2. Require `id` to match the expected peer when supplied; derive the DID
   from `verificationMethod` by parsing, not by a prefix-only string test.
3. Resolve the authoritative registry with chapter 09 freshness rules.
   Unavailable, inactive, stale, malformed or untrusted results fail closed.
4. Require exact record-version equality and identical `services` values.
   Resolve the named signing key and verify using that key alone.
5. Expose discovery data only after all checks succeed. Do not execute
   tools or treat card text as instructions during verification.

A key copied into a card cannot establish trust. A changed registry version
invalidates the old card even if its signature and lifetime still pass;
the issuer publishes a newly signed card. The sender may retry discovery,
but MUST NOT downgrade to unsigned discovery for a protected operation.

## 4. Security and compatibility

A-2/A-4 substitution is addressed by signer/record binding; A-6 stale cards
by current resolution and version equality. Signatures cannot show that
capability descriptions are truthful or that model interpretation is safe.
Trusted original requests and execution approvals are covered separately by
[the security integration profile](../profiles/agent-mcp-security.md).

The proof intentionally profiles [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html)
for canonical bytes; it is a SAGE construction requiring independent review
and future inspector tests. Existing custom JCS proofs mislabeled as W3C
suites are incompatible. No A2A schema version is implicitly negotiated.
