# Strict 0.10.0 DID syntax observation

The [20-case suite](../vectors/0.10.0/strict-did010.json) is derived from
`sage-spec` revision `fa006fd917ad365eb554a27f4178301cd66e2379`, chapter
06 ID-01/ID-02 and the `eip155`/`web` syntax in chapter 09. It distinguishes
canonical web and chain identifiers and key URLs from legacy aliases,
reserved kinds, mixed-case prefixes, invalid domains, malformed chain
locators and bad fragments. Inputs and expected outputs are fixed in the
Inspector suite, not generated by either core.

Go and Rust expose separate strict 0.10.0 parsing entry points. Inspector's
dedicated external adapters call those entry points and return the parsed kind,
locator, agent ID and optional key ID. The old `ParseDID`/`parse_did` paths
and shared historical adapters remain unchanged for legacy consumers. The historical [DID prefix
observation](did-prefix-observations.md), including its FAIL and UNSUPPORTED
results against older core revisions, is preserved.

The pinned core revisions are Go `be8c177653553c7fc4b91aafe5a4e39a68e6855f`
and Rust `1577ed80fef601284a999a3bfc460b57239a6d74`. Each matched all
20 expectations in a local external-process run. CI runs the same suite
against clean checkouts and preserves its own reports as artifacts.

CI builds both adapters against exact core commits, executes all 20 cases
in separate processes, and retains the runner's revision and executable
hashes. The report checker requires every expected verdict and parsed value
to match. These are **syntax-level results**. They do not establish registry
authority, resolved key status, expected-peer binding, proof verification,
or complete ID-01/ID-02 parent-case conformance. Those gates remain
`NOT_ESTABLISHED` until their integrated cases execute.
