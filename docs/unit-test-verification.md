# 시나리오 기반 단위 테스트 검증 범위

사용자 지시에 따라 현재 추가 검증은 단위 테스트로 진행한다. 실제 취약점 재현,
코어 동시성 진단 프로세스 실행, 실제 호스트 우회 시험 및 시뮬레이터 제작은
현재 실행 범위에서 제외한다. 기존 Inspector 단위 테스트에 race detector를
적용하는 것은 허용하며, 재현 프로그램을 실행하는 것과 구분한다.

과거 코어 실측과 실패 원문은 보존한다. 단위 테스트가 통과해도 기존 Go 종료 경합
FAIL, Rust 직접 병행 종료 UNSUPPORTED, 상태 시나리오 NOT_RUN을 변경하지 않는다.
전체 적합성은 NOT_ESTABLISHED이고, 386개 계획 사례의 실제 실행 집계도 유지한다.

## 세션 만료 검증

`scripts/test_session_expiry.py`의 8개 단위 테스트는 기존 고정 시나리오 6개를
재사용한다. 새 시나리오 파일을 배포하거나 기존 벡터와 해시를 수정하지 않는다.

| 검사 | 단위 테스트 범위 |
|---|---|
| 만료 경계 | 절대 수명, 유휴 수명, 임시 세션 확인 기한의 직전·경계·직후 9조합에서 보고서의 잘못된 수락·거부를 검출 |
| 부수 효과 | 만료 거부 시 accepted/dispatch/allocated/emitted/confirmations/closed 카운터 및 후속 상태·키 가용성·마지막 활동 시각 불일치를 검출 |
| 유휴 시간 | 시각 599의 잘못된 입력이 활동 시각 0을 갱신하지 않고 시각 600에 만료되는 고정 기대값 확인 |
| 처리 중 만료 | 임시 세션의 사전 확인 299, 수락 시점 300을 구분하고 commit_monotonic 입력이 누락된 보고서를 거부 |
| 절대 수명 유지 | 임시 세션 확인 이후에도 생성 기준 시각 3600에서 만료되는 고정 기대값 확인 |
| 검증 증거의 형식 | 불리언과 숫자를 구분하고, 누락된 단계·관측·효과와 미지원 시간 제어 이후의 허위 통과를 거부 |

기준은 고정된 `sage-spec/spec/05-session.md` SESSION-02와 기존 임시 세션 확인
시나리오다. 절대 3600초·유휴 600초는 설정된 최대 정책의 경계이며, 실제 구현은
더 이른 로컬 정책 종료를 선택할 수 있다. 이 테스트는 모든 구현이 반드시 해당
시각까지 세션을 유지해야 한다는 요구를 추가하지 않는다.

경계 변형은 테스트 메모리에서만 만든다. 관측은 고정된 스크립트이며 시간을 기다리거나
시스템 시각을 변경하지 않는다. 실제 암호 검증, 키 파기, 코어의 만료 처리나 동시
스케줄을 수행하는 모델/시뮬레이터를 만들지 않는다. 테스트 대상은 **Inspector의
보고서 판정과 고정 기대값**이며 실제 코어의 방어 구현이 통과했다는 의미가 아니다.

테스트로 확인한 보고서 검증기 문제 두 가지를 수정했다. Python의 `False == 0`
때문에 불리언을 숫자 카운터/시각과 혼동하던 비교를 JSON 타입을 구분하는 비교로
바꾸었다. NOT_RUN 단계에 관측이 첨부된 경우도 거부한다.

```sh
python3 scripts/test_session_expiry.py
python3 scripts/test_session_inspection.py
```

CI의 세션 검증 단계에 새 단위 테스트를 등록한다. 합성 보고서는 배포 증거로
출력하지 않고, 고정 증거 카탈로그와 코어별 결과 집계도 변경하지 않는다.
