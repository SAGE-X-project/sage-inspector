# sage-inspector

The new **0.10.0 conformance foundation** loads independently sourced test vectors,
runs a reference implementation or an explicitly selected core adapter, and writes
an evidence report. It lives in `pkg/conformance` and has no SAGE core imports.
The standalone command is `sage-conformance`; the historical `sage-inspector`
commands are retained separately and do not implement the revised profile.

## Run the new foundation

```sh
go run ./cmd/sage-conformance -suite vectors/0.10.0/foundation.json -report report.json
```

The bundled suite has **26 cases**: published HKDF/SHA-256 examples, canonical
base64url cases, and manually derived JSON rejection cases. Expected values are
stored in the suite and never generated by the subject during a run. A test vector
is an input/expected-output pair (or expected rejection), not a mathematical vector
space or an LLM embedding.

The default subject is `inspector-reference`. Its PASS checks the listed primitives
against frozen expectations; it does **not** certify Go SAGE, Rust SAGE, HPKE sessions,
registry resolution or Execution Guard. All 386 planned spec cases have not been
implemented. Rule IDs indicate relevance, not full rule coverage.

```sh
make build-foundation
make test-foundation
./bin/sage-conformance -suite vectors/0.10.0/foundation.json -case hkdf-a1
# exit3: one case PASS, the remaining25 NOT_RUN
```

## Connect another implementation

```sh
./bin/sage-conformance -suite vectors/0.10.0/foundation.json \
  -adapter /absolute/path/to/core-adapter -subject rs-sage-core \
  -revision ACTUAL_REVISION -timeout 5s -report rust-report.json
```

Adapters receive only case identity, operation and input over stdin; they never
receive expected output. One bounded JSON observation on stdout is compared by
Inspector. Real Go/Rust core adapters are available under `adapters/`. The
[example adapter](examples/reference-adapter/main.go) demonstrates the transport
using the same reference primitives, so it is **not a second independent core**.
See the [fixture/report/adapter contract](docs/conformance.md).

Exit codes: **0** all listed cases PASS; **1** observed failure; **2** invalid input,
configuration or report-write error; **3** incomplete (UNSUPPORTED or NOT_RUN).
Reports record source attribution, exact suite/input/request hashes, expected and
actual results, subject revision, executable hash when available, runtime and timing.
Empty, malformed, wrong-version or duplicate-case suites are rejected.

[Implementation verification](docs/foundation-verification.md) records this delivery's
checks and limits. [Legacy commands](docs/legacy-commands.md) document the older
core-linked tools. This foundation does not change existing core implementations,
protocol documentation or historical vectors.
